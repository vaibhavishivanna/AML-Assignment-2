`FashionMNIST0.6.npz` and `CIFAR.npz` in `code/data/`. Only `data/.gitkeep` is

From `code/`, use Python 3.12 and run:


## Short functional test and supported options

Staff permit fewer repetitions for functional testing. This retains the training
settings but does not reproduce the report's ten-run statistics:

```sh
python run_evaluation.py --runs 1 --workers 4 --threads 1 --out quick_check
python verify_evaluation.py --results quick_check
```

Paired t analysis needs at least two pairs; the report figure exporter requires
ten. Do not run them on a one-repetition check. A separate quick-check runtime
has not been measured for this updated package.

`--seed-start` is supported. For example, `--seed-start 7 --runs 2` runs seeds
7 and 8; verification and paired analysis discover actual saved seed numbers
instead of assuming zero. Verification also accepts the runner's optional
`--fashion-estimated` comparisons. Both analysis and verification require an
explicit `--results` folder and never silently select a historical experiment.

The default data folder is relative to the scripts, independent of the launch
working directory; `--data-dir PATH` selects another location. Four workers with
one thread is the measured fast profile on the tested eight-logical-CPU Mac.
The lower-memory fallback remains `--workers 2 --threads 2`.

## Algorithms and experiment settings

- Ten random 80/20 holdouts, seeds 0–9, shared by the classifiers.
- Four estimator epochs and ten high-posterior training anchors per class.
- Four Forward epochs.
- Reweight-R: two noisy-label CE warm-up epochs, four detached-importance-weight
  epochs and eight joint Forward-loss revision epochs.
- Supplied FashionMNIST matrices; per-split estimated matrices for CIFAR.
- Shared CNN and training-split channel standardization; no augmentation or cleaning.
- Noisy-validation checkpoint selection; clean labels only for final testing.
- Descriptive accuracy SD uses ddof=0; paired t inference uses ddof=1, individual
  95% intervals and Holm adjustment across all dataset/mode comparisons exported.
- Algorithms have unequal optimization budgets. Classification gains do not
  establish improved transition recovery or isolate the effect of revision.

The classifier is labelled **Reweight-R**. Its implementation class
`ReweightTRevision` and the historical standalone registry key `T-Revision` remain
for compatibility; it is a modified hybrid, not an exact reproduction of Xia et al.
PyTorch is used for the CNN and optimization as permitted by staff clarification.

## Transition convention

Every component uses `T[i,j] = P(noisy=j | clean=i)`: clean rows, noisy columns.
Rows sum to one and `p_noisy = p_clean @ T`. `transition_matrix.py` defines and
validates this contract. The lecture's opposite indexing is `T_lecture = T.T`;
do not transpose supplied matrices in our formulation. For FashionMNIST0.3,
clean class 0 flips to noisy class 1 with probability 0.3, and to class 2 with
probability zero. Stochasticity alone cannot detect a transpose of a doubly
stochastic matrix; directional tests and saved classifier inputs are also checked.

Staff allow either, both or neither robust method to use a transition matrix.
Our methods use matrices consistently for supplied and estimated settings.

## Additional controlled study

The completed ten-seed supplementary study measured **2h 26m 05.59s** with four
workers and one thread each on the same Mac. This is additional to the historical
58m 33.20s canonical evaluation, and is not a new timing of that original pipeline.
The full study contains 30 dataset/seed cases plus ten CIFAR settings in each of
two fixed-fold arms. Its saved predictions, source/data hashes and all learning
curve epochs are checked before report tables are exported.

The extra study addresses experimental feedback; it is separate from the previously
measured canonical evaluation and adds training time. It replays the four-epoch
preliminary model as a plain-CE baseline, trains epoch-matched Forward14, and
replays Reweight-R to recover the exact pre-revision checkpoint. An eight-epoch
fixed-matrix continuation then shares that checkpoint, optimizer settings,
minibatch order and dropout random stream with learned revision. Replayed
matrices/predictions must match the baseline; a mismatch aborts the case.

Anchor counts 1/5/10/20 are compared on the same preliminary posteriors. Temperature
scaling uses half the noisy validation split, with calibration checked on the other
half (the full split was previously used for epoch selection). CIFAR fixed-fold
controls separately vary classifier or estimator randomness. Clean test labels
are used only after fitting; they do not tune temperatures, k or checkpoints.
All final contrasts use ten pairs, individual t intervals and Holm adjustment
across six controlled hypotheses. The one-fold CIFAR controls do not provide a
global variance decomposition. No superiority or recovery claim is hard-coded.

For a shorter functional check, first generate all three baseline seed-0 cases
with `--runs 1`, then run `run_report_controls.py --baseline quick_check --out
quick_controls --runs 1 --workers 4 --threads 1`. Do not summarize that as the
ten-run report: the final summarizer deliberately requires all ten repetitions.
